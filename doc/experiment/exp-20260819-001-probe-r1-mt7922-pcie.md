# EXP-20260819-001 探测 R1 MT7922 PCIe 枚举与驱动绑定

## 目标

确认学习者购买的 MT7922 是否能通过 R1 顶部 M.2 E-Key 的 PCIe 链路被枚举，以及当前 Rockchip 5.10.252 RAM 候选是否有驱动绑定。

## 环境与前置条件

- 执行端：R1 目标 Linux Bash。
- 硬件及版本：youyeetoo R1 V2；学习者购买的 MT7922，具体商品型号与天线型号未记录。
- 软件、镜像或 Git commit：此前通过 userdata→RAM 启动的 Linux 5.10.252、RKNPU 0.9.8、无 Rockchip display DRM/无 Mali 候选。
- 连接方式：MT7922 安装于 R1；具体断电、安装和天线连接过程未记录，不能补写为已验证步骤。
- 操作前状态：候选系统已经启动；eMMC boot 分区保持不变。

## 风险与恢复

- 影响范围：本次保存的命令仅读取 PCI 与 sysfs 状态；M.2 卡的安装属于硬件状态变化，但操作过程没有完整证据。
- 备份：不适用。
- 恢复方法：若需拆装，必须关机、断开所有供电并等待板上电源消失后操作；本实验未执行拆卸。

## 步骤与证据

### 步骤 1：读取 PCI 设备标识

目的与预期结果：验证卡是否越过机械连接、供电和 PCIe 链路训练，成为 Linux 可见 PCI 设备。

实际输出（学习者提供；原命令和退出码未单独记录）：

```text
0004:41:00.0 Network controller [0280]: MEDIATEK Corp. Device [14c3:0616]
```

观察：

- **已验证**：PCI domain/bus/device/function 为 `0004:41:00.0`，厂商/设备 ID 为 `14c3:0616`。
- **资料记载**：Linux 上游 `drivers/net/wireless/mediatek/mt76/mt7921/pci.c` 将 MediaTek `0x0616` 映射到 `MT7922_FIRMWARE_WM`；驱动模块名仍为 `mt7921e`。
- 该枚举证据支持卡的 PCIe 功能已可见，但不单独证明 Wi-Fi、蓝牙、射频、天线或固件可用。

### 步骤 2：检查驱动绑定

目的与预期结果：确认 PCI 设备是否已有当前内核驱动接管。

实际输出（学习者提供）：

```text
0004:41:00.0 Network controller [0280]: MEDIATEK Corp. Device [14c3:0616]
	Subsystem: Foxconn International, Inc. Device [105b:e0cd]
lspci: Unable to load libkmod resources: error -2
```

随后通过 `/sys/bus/pci/devices/0004:41:00.0/driver` 是否为符号链接进行不依赖 libkmod 的复核，学习者报告结果为：

```text
unbound
```

观察：

- **已验证**：当前没有内核驱动绑定到 MT7922 PCIe function。
- `lspci` 的 libkmod `error -2` 与候选系统缺少 `/lib/modules/5.10.252` 的既有状态相符；sysfs 复核不依赖这一数据库。
- **已验证（主机源码）**：当前 Rockchip 5.10.252 候选源码的 MediaTek `mt76` 子树没有 `mt7921` 目录，候选 `.config` 也没有 `CONFIG_MT7921E`。因此问题不只是缺一次 `modprobe`。
- **资料记载**：Linux Wireless 文档将 MT7922 PCIe 支持标为 Linux 5.16+。当前 Rockchip 5.10 树若要使用它，需要评估整套驱动回移、固件和模块部署，而非只打开一个现有配置符号。

## 结果对照

| 检查项 | 预期 | 实际 | 判定 |
| --- | --- | --- | --- |
| M.2 E-Key PCIe 枚举 | 出现 MediaTek 网络控制器 | `14c3:0616` | 通过 |
| MT7922 身份 | 上游驱动表匹配设备 ID | `0x0616` → MT7922 firmware | 通过 |
| 当前内核驱动绑定 | 出现 `Kernel driver in use` 或 sysfs driver | `unbound` | 未通过 |
| 当前 5.10 源码支持 | 存在 `mt7921e` 代码与配置 | 代码目录和配置均缺失 | 未通过 |

## 结论

MT7922 的 PCIe 功能已经在 R1 上成功枚举，说明本次可见范围内的插槽供电和 PCIe 数据通路可工作。当前 Linux 5.10.252 RAM 候选没有可绑定的 `mt7921e` 驱动，Wi-Fi 不能立即使用；蓝牙 function 是否经 USB 枚举尚未检查。学习者决定暂缓该支线，继续使用有线网络推进 AMP 主线。
