# 学习路线

路线按“能够解释、能够操作、能够根据证据排障”推进，不以看完资料作为完成标准。阶段状态以 [`status/current.md`](../status/current.md) 为准。

| 阶段 | 核心内容 | 完成标准 | 当前状态 |
| --- | --- | --- | --- |
| 0. 环境与设备识别 | 板型、接口、供电、主机工具、恢复入口 | 环境基线完整，建立至少一种调试链路，明确恢复方法 | 进行中 |
| 1. 启动链路 | BootROM、SPL、U-Boot、启动介质 | 能结合日志解释各阶段并定位启动停在哪一层 | 交叉进行（只读勘察） |
| 2. Linux 系统组成 | 内核、设备树、根文件系统、用户空间 | 能构建或替换单一组件并验证影响 | 进行中（基础观察） |
| 3. 内核与驱动基础 | 驱动模型、platform、GPIO、I2C、SPI、中断 | 完成一个小型驱动实验并能解释绑定流程 | 未开始 |
| 4. 调试与性能 | 日志、动态调试、追踪、资源和温度 | 能设计最小实验定位一个真实问题 | 未开始 |
| 5. 边缘 AI | NPU 运行时、量化 LLM、模型转换与部署 | 证明 R1 NPU 实际完成 LLM 推理，并记录来源、内存和性能 | 进行中（运行时可用性核查） |
| 6. 综合项目 | 板端事件采集、NPU LLM 与 systemd 服务整合 | 形成可复现的 R1 NPU LLM 边缘事件助手及完整复盘 | 未开始 |
| 7. Linux+Zephyr AMP（长期） | CPU、内存、外设所有权与跨系统通信 | 在已验证平台能力上完成可复现的最小 AMP 原型，并量化隔离与通信指标 | 未开始 |

阶段可交叉进行，但不得跳过与高风险操作直接相关的硬件识别和恢复准备。

阶段 7 的方向与边界见[DEC-20260810-002](../decision/dec-20260810-002-linux-zephyr-amp-long-term-direction.md)。它不替代阶段 0–6 的前置学习，也不预设当前厂商系统具备 Zephyr、EL2 或 IOMMU 支持。

阶段 5–6 的近期项目边界见[DEC-20260813-003](../decision/dec-20260813-003-npu-llm-required-project-core.md)：NPU 上实际运行 LLM 是必选验收项，Zephyr AMP 仍为后续扩展。
